# Design v2 — notes for future passes (2026-10-07)

## What changed from v1 and why
v1 was the generic default: cream #F4F1EA + serif + gold accent, ALL-CAPS eyebrows on every heading, 01/02/03 markers on non-sequences, middle-dot meta strings, fade-up on every section. Scrapped.

v2 grounds everything in the subject — shade, porcelain, how white reads against skin:
- **The one bold element:** `ShadeStudio` (Monk 10-tone scale + undertone + 6 VITA-style tabs + translucency → plain-language "reads as" verdict). Homepage hero runs the compact version; /smile-design runs the full one.
- **Color:** porcelain #F2F1ED + enamel-ink #16181B. No decorative accent; color appears only where it means something (shade tabs, skin tones). Gold survives only as the wordmark's period.
- **Type:** Newsreader (variable, opsz axis, weight 300 at display) + Hanken Grotesk. Italics apply to whole lines, never a single word.
- **Structure as information:** `.steps` numbering only on true sequences (4 visits, consult hour). `.facts` definition lists replace cards. Eyebrows removed; `.kicker` only where it carries data (Case 02).
- **Motion:** one load moment per page (`.rise` masked line rise desktop; single block rise on phones). Lenis smooth scroll. Everything else answers a user action: ShadeStudio, CompareSlider, PaymentSlider, ConsultPlanner. No per-section reveals.
- **ROI mechanics:** PaymentSlider (term → monthly with Reg Z disclosure attached), CompareSlider for cases, ConsultPlanner (3 taps prefill the request), sticky Call/Book bar, header CTA.

## Gotchas hit
- next/font: variable fonts with `axes` cannot also set `weight` — Newsreader config has no weight array.
- `[class^="c-"]` grid-collapse selector misses `class="lede c-1-6"`; use `.grid > *` in the media query.
- Per-line `.rise` masks wrap badly on phones; ≤640px switches to inline spans with `::after { content: " " }` and one block rise.
- Running `next build` while `next dev` is up corrupts `.next` → 500s. Stop dev first or build to a separate distDir.
- `backdrop-filter` on the sticky header makes it the containing block for `position: fixed` descendants — the mobile menu rendered as a 68px-tall transparent strip with links spilling over the page. Menu is now portaled to `<body>` (`.menu`), header pauses Lenis via `window.__lenis` while open.
- Inline `style={{ gridRow: 1 }}` beats the mobile `.grid > *` reset and pushed the Cases compare slider off-canvas. Use the `.row1` class instead so the media query can release it.

## Dentition model v2 — real teeth, real breakage, stains (2026-10-08)
Brady: chips "don't have enough polygons and don't look real", "how is the chip upside down so the damn tooth is floating", "make the teeth look more decrepit", "I almost want stain textures", model should only turn left/right. Everything below is in `components/TeethModel.tsx`.
- **Segmentation is exact now:** union–find over the glTF indices (position hash as fallback for non-indexed input) → 32 shells. Arch per shell = where its open gum-line edge sits relative to the crown centre (boundary edges = edges used by one triangle). Front six upper teeth get 2 Loop-subdivision iterations (`three-subdivide`, `preserveEdges: true`, tangents dropped), everything else 1; gums 1. ~68k tris total, ~0.5 s prep, runs twice under StrictMode only (default regex props were hoisted — they used to re-run the whole prep on every slider move).
- **Chip = CSG** (`three-bvh-csg` + `three-mesh-bvh@0.9`, installed with `--legacy-peer-deps` because drei pins bvh 0.8): a lumpy icosphere (R = 1.15 × crown height, centre **in front of** the labial face so the shear leaves a forward-facing bevel) subtracted from the right central at the mesial-incisal corner (Ellis-II look). Result carries two material groups: enamel shell + a dull dentin material (DoubleSide). The intact tooth sits underneath with `polygonOffset` and a shader `discard` inside the same sphere (`uChipC/uChipR`, in the tooth's local frame); as the slider moves the radius shrinks (0.2→0.7) and the corner regrows; the chipped copy hides once covered. Clipping planes are gone.
- **Before-state posing** (`kind: 'pose'`, rotation + offset from `home`, per-damage window): left lateral missing, both neighbours drifted toward the space, diastema between centrals (chipped one shifted + greyed `uGrey`), right lateral turned and tucked lingually, canine standing proud. Teeth materials are DoubleSide so open shells never read as black holes.
- **Procedural staining** in the fragment shader (3D value-noise fbm, no texture files): per-vertex `aGum` (0 = biting edge, 1 = gum line) drives cervical darkening, brown blotches (`stain`), fine speckles, and a lumpy calculus crust at the gum line (`tartar`), heavier on side-facing (interproximal) surfaces via `vNormal.x`. All of it whitens with `uMix`; the front band then goes to porcelain via `teethMix`. Intensity knobs are the smoothstep thresholds in `patchVeneer`.
- **Per-tooth variation + crack (Brady: "WAYY heavier", "don't stain every tooth equally", "some teeth need to look better than others", "maybe add some kind of crack"):** each shell gets a constant `aSeed` attribute; the shader derives `dirt = 1.8·tv^1.8` (most teeth modest, a few filthy, some nearly clean), `crust` (calculus only on some teeth), and a per-tooth base yellow. One upper tooth (`uCrackSeed` = the left central beside the gap) carries a hairline craze line: a jittered path in the tooth's local x vs `vGum`, labial-facing only (`vNormal.z`), plus a short branch — it whitens away with `uMix` like the stains. Intensity knobs: the `dirt`/`crust` formulas and the `stain`/`tartar` smoothsteps.
- **Veneer set, not a depth band (Brady: back teeth "need to not be in as bad of shape… veneers don't always include back teeth"):** each tooth carries `aVeneer` = 1 for upper centrals→first premolars (eight teeth, `|theta| ≤ 0.7`), else 0. Porcelain (`teethMix`) and the heavy neglect key off that flag; non-veneer teeth (premolars/molars and the whole lower arch) are only mildly dingy before and get a light clean-up after (`polish = uMix·mix(0.45, 1, aVeneer)`), so the after state reads as eight veneers over cleaned natural teeth. The old `uZCut/uFeather` depth band is still passed in but unused.
- **QA while the pane is hidden:** a background pane pauses rAF *and* ResizeObserver, so a freshly loaded R3F canvas never measures (300×150) and `useFrame` never runs. `preview_start({url})` opens a new tab that initialises; then `window.__teethFrame(n)` (dev hook, calls R3F `advance`) steps the loop by hand before `toDataURL`.
- Pointer rig rotates on Y only (no nodding). `/lab/teeth` now lists only the Antipov model; the Poly-by-Google GLB was deleted.
